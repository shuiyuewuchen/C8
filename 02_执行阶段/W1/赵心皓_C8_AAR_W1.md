# Weekly AAR — Week 1：数据桥接与统一 schema

## 预期（R̂）

本周计划产出（来自 Proposal Part 3）：
- Layer 1 桥接器 + 统一 Message schema + SETUP；
- ≥120 条群消息、≥5 种消息类型；
- CLI 可重复运行、支持时间范围参数。

## 实际（R）

- `wcm/core.py`、`wcm/bridge.py`、样本生成器、SETUP 均已交付；
- 生成 **168** 条脱敏消息、**5** 种消息类型（text/file/link/image/voice）；
- `messages.jsonl` 为统一 schema，独立标注表 `labels.json` 与消息流分离；
- fixture 适配器重复运行结果一致，`--days` 参数可用；
- **未完成**：`cli` 适配器未在真实微信数据库上验证。

## 差值（ΔR = R̂ − R）

| 指标 | R̂ | R | ΔR（相对误差） |
|---|---:|---:|---:|
| 消息数 | 120 | 168 | +40%（超出预期） |
| 消息类型 | 5 | 5 | 0% |
| 可重复运行 | 全部适配器 | 仅 fixture | **部分未达** |
| 数据窗口参数 | 支持 | 支持 | 0% |

- **完成了什么**：离线链路完整跑通，schema 稳定，数据可复现。
- **没完成什么**：真实微信接入验证；另外我原以为 120 条足够，实际生成 168 条——
  说明我对"一份能撑起统计意义的样本"的体量估计偏低。
- **意外发现**：macOS 上 `wechat-cli init` 需要终端完全磁盘访问权限，
  这不只是安装步骤，而是**需求约束**：它意味着"随时接入真实群"在受限环境里不成立。

## 失败分析

- **哪里失败了**：真实数据适配器的验证环节。
- **根本原因**：构建环境没有已登录的微信实例与相应系统权限；
  我写 proposal 时把"工具可用"默认成了"数据可得"。
- **不是根本原因但看起来像的**：
  - "wechat-cli 不兼容"——不是，文档显示支持 macOS arm64；
  - "代码写得不对"——不是，CLI 调用逻辑已完成，缺的是运行环境；
  - "样本数据不够真实"——这是结果，不是原因。
- **由此得到的教训**：真实项目与练习最大的差别，是**环境本身可能是阻塞项**。
  练习里可以假设数据源存在；真实项目必须先确认数据源的访问权。

## 本周我发现了____，它比我之前的方案更好，因为____

本周我发现了 **wechat-cli 官方 README 中的"只读 + 数据不出本机"设计与权限前置条件**，
它比我之前"直接写一个脚本读数据库"的方案更好，因为：
① 只读原则直接消除了"误写群消息"的风险；
② 显式权限步骤让我提前一周识别环境阻塞，而不是在 W7 才发现；
③ JSON-first 输出省掉了自己写解析器的工作。
