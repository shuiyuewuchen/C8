# 赵心皓_C8_W1_拿来更新.md

## 本周新评估的来源

**来源**：wechat-cli 官方文档（中文 README）
**链接**：https://github.com/freestylefly/wechat-cli
**发现渠道**：Proposal 阶段检索时的延伸阅读，本周细读到"初始化"与"权限"章节。

## 核心新信息

1. `sudo wechat-cli init` 依赖从微信进程内存提取 SQLCipher 密钥；
2. macOS 需要为终端开启"完全磁盘访问权限"；
3. 部分系统出现 `task_for_pid failed`，工具会自动尝试对微信重新签名；
4. 明确 `只读不写`、`数据不出本机`，且提示存在冒名 fork 可能外泄数据。

## 判断：采用 / 丢弃 / 重构

- **采用**：只读原则、官方仓库作为唯一安装来源、权限前置步骤。
- **丢弃**：任何"绕过权限直接读库"的取巧方案。
- **重构**：把权限要求写进 `SETUP.md` §3.2，并在 W1 AAR 中把"环境权限"列为独立风险，
  而不是等到接入阶段再处理。

## 对现有方案的影响

原计划"随时可切换到真实数据"被修正为：
**先在脱敏数据上完成全部开发，真实接入作为独立里程碑（W5）并带现场条件检查清单。**

这是本周最重要的方案调整——它来自一个新来源，而不是来自我自己拍脑袋。

## 本周结论句

本周我发现了 **wechat-cli 的密钥提取依赖系统权限与官方仓库防伪提示**，
它比我之前的方案更好，因为它把"数据源可得性"从隐含假设变成了显式前置条件，
使项目计划从第一天起就符合真实世界的约束。
