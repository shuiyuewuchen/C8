# 赵心皓_C8_W3_拿来更新.md

## 本周新来源：Agent Skills 开放规范

- **链接**：https://agentskills.io/specification
- **核实要点**：
  - `name` 必填，1–64 字符，小写字母/数字/连字符，必须与目录同名；
  - `description` 必填，1–1024 字符，需同时说明"做什么"和"何时用"；
  - 可选字段 `license`、`compatibility`、`metadata`、`allowed-tools`；
  - 正文推荐包含步骤、输入输出示例、常见边界情况；
  - 渐进式披露：Agent 平时只加载 name + description（约 100 tokens/skill）。

## 采用 / 丢弃 / 重构

- **采用**：frontmatter 规范、目录即 skill、渐进式披露理念。
- **丢弃**：我原先自造的" Skill 说明模板"——字段不统一，无法被其他 Agent 识别。
- **重构**：
  - 6 个 SKILL.md 全部改为规范 frontmatter；
  - 在规范之上新增项目特有的 Inputs / Outputs / Edge cases / Run 四段；
  - description 中加入可检索关键词（如 `submission`, `missing AI log`, `nudge`, `FAQ`）。

## 影响

这是一次**真实替换**：从私有约定换成开放标准。
直接收益是 skill 可被任何支持该规范的 Agent（Claude Code、Codex、Cursor 等）识别，
符合 C4「可复用技能」与 C8「别人能接手」的要求。

## 评估后维持原方案的记录

本周同时评估了 **Neo4j 原生图查询** 作为图后端替换方案：

- 优势：Cypher 表达多跳关系更自然；
- 成本：需要额外服务、端口、鉴权与备份；24×8 的数据规模远未到必要程度；
- **结论**：现有 SQLite `PropertyGraph` 仍然最优，因为"评审者可用 sqlite3 直接打开验证"
  对 C8 的验收价值高于图查询语言表达力。
  升级路径已在 `docs/architecture.md` 写明：保持 `PropertyGraph` 接口，替换后端即可。

## 本周结论句

本周我发现了 **agentskills.io 开放规范**，它比我之前的自造格式更好，
因为它让 6 个 Skill 从"只有本项目能读的说明文本"变成"任何兼容 Agent 都能加载的标准能力包"，
并且规范要求的 description 写法倒逼我把触发条件写清楚，直接提升了可复用性。
